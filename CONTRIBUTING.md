# Contributing to Weft

Weft welcomes corrections from anyone who reads these languages, and especially from scholars.
`docs/about.md` explains what the library is and why it is built the way it is;
`docs/languages.md` sets out what each pronunciation scheme rests on.

There are two routes. Both end in the same place: a correction recorded under your name, which can
be reviewed, discussed and undone.

## Without git: the forms

Open an issue on GitHub and choose the form that fits. Each page links to the correction, pronunciation and recording forms, with
the work and the pronunciation scheme you are reading in already filled in.

| Form | Use it when |
|---|---|
| Correction | a gloss, lemma, grammatical form, scansion, alignment or note is wrong |
| Pronunciation | a sound or a rule is wrong, or a scheme should be added; a citation is required |
| Offer a recording | you would read a passage aloud in one of the schemes |
| Propose a text | a passage belongs in the library |

To find what to cite, tap the word on the page: the word panel shows its id (for example
`od.1.1.5`, the work, line and word) and what produced each value. Tapping a line number shows the
line id. A maintainer writes the correction into the repository,
credits you as you ask (a name or a pseudonym), and links the change from the issue.

## With git: write the correction yourself

### The one rule

Never edit `texts/*/gen/`. It is regenerated by the pipeline. Your judgment goes in
`texts/<work>/curated/`, where it overrides the generated layer and keeps your name on it.

### Correcting a gloss, a parse, a scansion or a note

1. Open the work's curated file, for example `texts/homer-odyssey/curated/book01.yaml`.
2. Add a changeset: who you are, the date, why, and the fields you set:

   ```yaml
   - by: A. Scholar
     date: 2026-10-02
     why: keep the etymology visible; the smooth reading belongs in the translation
     status: reviewed
     set:
       od.1.1.5: {gloss: much-turned}
   ```

3. Quote any value YAML might read as a boolean (`"on"`, `"no"`).
4. Run the checks and rebuild:

   ```
      uv venv && uv pip install -e .

   .venv/bin/weft check <work>
   uv run --with pytest pytest -q tests
   .venv/bin/weft build all
   ```

5. Open a pull request. One changeset per pull request keeps review simple.

Marking a changeset `status: reviewed` lifts the "draft" label on the fields it sets; the page's
draft notice goes when no unreviewed field remains. Only do that for
material you have checked yourself.

## Pronunciation: corrections and recordings

Every page opens with Weft's reconstruction of how the text sounded when it was first written, or
of the nearest stage that can be reconstructed. For some languages
that guide rests on good evidence; for others (Egyptian, Sumerian, Akkadian, the runic inscriptions)
it is a reconstruction that specialists still debate, and those pages say so at the top.

If you work on the phonology of one of these languages, corrections are welcome:

1. Use the Pronunciation form (the page's link fills in the work and the scheme), or edit the
   language's module or data files in `pipeline/weft/` and open a pull request.
2. Say what should change, for which words or which rule, and give the source: a grammar, an
   article, a corpus. A pronunciation change is only made with a citation.
3. After a rule change, run `weft acquire` and `weft draft` for each work in that language; the pull
   request then shows the change to each generated file, which is how its reach is reviewed.
4. If you would add a new scheme rather than change one (a different reconstruction, or a regional
   tradition), say so; schemes sit side by side and the reader chooses.

Recordings are welcome too. Weft does not play audio yet (it is planned), so recordings are
collected now and wired in when the audio layer lands:

- Read from the page, one file per line, named by the line id (tap the line number to see it; for
  example `gen.1.1.wav`), in one scheme, and say which.
- WAV or FLAC, 44.1 kHz or better, a quiet room, the line read at a natural pace.
- Release the recording under CC BY-SA 4.0 or CC0, and say how you want to be credited (a name
  or a pseudonym). Weft does not publish contact details.
- Use the Offer a recording form, and attach the files or give a link.

## Proposing a text

A work can be built when four things exist:

1. An edition of the original that is public domain or openly licensed (CC BY-SA, CC BY, CC0).
   Licences that forbid commercial use cannot be used.
2. At least one public-domain English translation. Translations still in copyright can be cited as
   references; the page names them without printing them.
3. A way to establish lemma and grammar: a treebank, or a good dictionary for hand annotation.
4. Some evidence for how the language sounded when the text was written.

Use the Propose a text form; blanks are fine. To build one yourself, start with the manifest:
edition, treebank (or `treebank: null`), pronunciation schemes with the as-first-written
reconstruction first, translations with licences, and the gaps you predict. See
`docs/lifecycle.md` and `docs/schema.md`.

## Adding a translation

Translations must be public domain or openly licensed. Add the translation to the work's manifest
with its licence, then align it: verse-numbered Bibles align automatically with `weft align <work>`;
other texts get a hand-made file in `texts/<work>/sense/`.

## Your own layer: private material and private works

Material you own or may use privately but cannot publish stays in `private/`, which is never
committed. A folder `private/<work>/` either adds to a public work (a translation you bought, your
own changesets, notes that quote at length) or, when no public work has that name, holds a whole
private work of your own. `weft build all --private` writes your library, public and private
together, to `private/build/`, which is never committed or published. `private/README.md` is the
guide.

Enable the leak guard once per clone; it refuses any commit that stages a private or fetched file:

    git config core.hooksPath .githooks
