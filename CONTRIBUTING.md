# Contributing to Weft

Weft welcomes corrections from anyone who reads these languages, and especially from scholars.

## The one rule

Never edit `texts/*/gen/`. It is regenerated by the pipeline. Your judgment goes in
`texts/<work>/curated/`, where it overrides the generated layer and keeps your name on it.

## Correcting a gloss, a parse, a scansion or a note

1. Open the work's curated file, for example `texts/homer-odyssey/curated/book01.yaml`.
2. Add a changeset: who you are, the date, why, and the fields you set:

   ```yaml
   - by: A. Scholar
     date: 2026-10-02
     why: keep the etymology visible; the smooth reading belongs in the translation
     status: reviewed
     set:
       od.1.1.5: {gloss: much-turned}
   ```

3. Quote any value YAML might read as a boolean (`"on"`, `"no"`).
4. Run the checks and rebuild:

   ```
   uv venv && uv pip install -e .
   .venv/bin/weft acquire <work> --accept-licenses
   .venv/bin/weft check <work>
   uv run --with pytest pytest -q tests
   .venv/bin/weft build all
   ```

5. Open a pull request. One changeset per pull request keeps review simple.

Marking a changeset `status: reviewed` lifts the "draft" label on the page. Only do that for
material you have checked yourself.

## Pronunciation: corrections and recordings

Every page shows how the text most likely sounded when it was first written. For some languages
that guide rests on good evidence; for others (Egyptian, Sumerian, Akkadian, the runic inscriptions)
it is a reconstruction that specialists still debate, and those pages say so at the top.

If you work on the phonology of one of these languages, corrections are welcome:

1. Open an issue from the page (the link prefills the work and the scheme), or edit the language's
   module or lexicon in `pipeline/weft/` and open a pull request.
2. Say what should change, for which words or which rule, and give the source: a grammar, an
   article, a corpus. A pronunciation change is only made with a citation.
3. If you would add a new scheme rather than change one (a different reconstruction, or a regional
   tradition), say so; schemes sit side by side and the reader chooses.

Recordings are welcome too. Weft does not play audio yet (it is planned), so recordings are
collected now and wired in when the audio layer lands:

- Read from the page, one file per line, named by the line id shown in the word panel
  (for example `gen.1.1.wav`), in one scheme, and say which.
- WAV or FLAC, 44.1 kHz or better, a quiet room, the line read at a natural pace.
- Release the recording under CC BY-SA 4.0 or CC0, and say how you want to be credited (a name
  or a pseudonym). Weft does not publish contact details.
- Attach the files to the issue, or offer a link, and Weft will add them with your credit.

## Adding a translation

Translations must be public domain or openly licensed; copyrighted ones belong in `private/`,
which is never committed. Add the translation to the work's manifest with its license, then
align it: verse-numbered Bibles align automatically with `weft align <work>`; other texts get a
hand-made file in `texts/<work>/sense/`.

## Adding a work

Start with the manifest: edition, treebank (or `treebank: null`), pronunciation schemes with the
as-first-written reconstruction first, translations with licenses, and the gaps you predict.
See `docs/lifecycle.md` and `docs/schema.md`.
