# Make weft ocr witness_check order-aware so a line cannot match a misplaced or truncated stretch of the witness

## Problem

pipeline/weft/ocr.py witness_check tests `want in witness`: each edition line, with declared ocr readings substituted, need only occur somewhere in the witness. It ignores order and line edges. On 2026-10-13 a skeptic found Article I ocr fields (made by a per-line best-window script) that passed the check while one line (a1s1.13) borrowed its readings from a different printed line (a28) and ~15 line edges dropped OCR letters. The data were regenerated by an in-order word alignment, but the sensor still cannot see the class.

## Approach

Make the sensor order-aware: walk the edition's lines in order through the joined witness, each match starting at or after the previous match's end, and report (a) a line found only before the cursor (misplaced) and (b) witness letters left unattributed between consecutive lines beyond a small noise allowance (truncated edges). Keep it per edition (state keyed by work) so repeated checks in one process start fresh.
